# Robot Type Packs

<p class="kicker">Applied payload layer</p>

Core Retriever teaches the runtime. Golden keeps the robot-facing vocabulary that examples can share: world state, belief, skills, plans, stamped spatial values, event buffers, dataset records, and export profiles.

<div class="card-grid">
  <a class="info-card" href="/robot-type-packs/type-catalog/"><strong>Type catalog</strong><span>Choose payloads for robot state, observations, plans, trajectories, status, and stamped values.</span></a>
  <a class="info-card" href="/robot-type-packs/flow-contracts/"><strong>Flow contracts</strong><span>Wire robot payloads through reusable Flows without dict glue or hidden field collisions.</span></a>
  <a class="info-card" href="/robot-type-packs/data-event-streams/"><strong>Data and event streams</strong><span>Record, join, window, replay, and export event streams without losing timing/provenance.</span></a>

## Start Here

```bash
pixi run demo-robotics-typing-catalog
pixi run demo-robotics-typing-contract
pixi run demo-robotics-typing-boundary
```

Expected result: terminal output showing stamped spatial payloads, composite I/O access rules, and a perception-to-control boundary that preserves frame, time, and source metadata.

## What Golden Owns

| Area | Golden provides | Core Retriever provides |
| --- | --- | --- |
| Robot payload vocabulary | `WorldState`, `BeliefGraph`, `Skill`, `Plan`, `Trajectory`, status, and stamped robotics examples. | Canonical runtime, clocks, Flow/Pipeline execution, IR, replay, and registry mechanics. |
| Composition contracts | Public examples for composite I/O, qualified fields, and validation boundaries. | The composition/runtime semantics used by those examples. |
| Event/data profiles | `Event`, `EventBuffer`, event-time joins, manifests, and LeRobot bridge examples. | Runtime event-buffer mechanics and scheduler behavior. |
| Hub readiness | Pack boundary, export catalog, smoke demos, and promotion guidance. | Hub loader and registry integration. |
