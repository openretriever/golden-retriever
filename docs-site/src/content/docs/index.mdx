<div class="boundary-note">
<strong>Golden is not a second runtime.</strong> Install and learn Retriever once. The Python import package is <code>retriever</code>; Golden provides applied examples and pack candidates on top of that runtime. If you need Flow, Pipeline, clocks, sync, or replay semantics, use the core runtime docs; otherwise stay on this Golden path.
</div>

## Quick Start

Run the smallest Golden proof before choosing a heavier example lane.

```bash
pixi run demo-golden-hub-pack
```

<details class="explain-details">
  <summary>What does this do?</summary>
  <div>
    <p>The command loads the Golden robot payload pack through Retriever Hub, constructs representative payloads, and round-trips a command through Arrow helpers. It requires no robot, camera, simulator, model, network service, or GUI.</p>
  </div>
</details>

## Why Golden Retriever

<div class="check-list">
  <p><strong>Applied layer, not another runtime.</strong> Core Retriever owns Flow, Pipeline, clocks, sync, IR, replay, and execution. Golden owns robot-facing examples and payload-pack candidates.</p>
  <p><strong>Mock-safe first.</strong> The first commands should work before camera, simulator, GPU, model, or robot dependencies enter the loop.</p>
  <p><strong>Expected artifacts.</strong> Each promoted lane should say what output to recognize: terminal proof, mock trace, HTML graph, Rerun stream, or dataset/export artifact.</p>
  <p><strong>Pack promotion path.</strong> Useful examples can mature into Hub-loadable packs once their imports, tasks, docs, and smoke tests are stable.</p>
</div>

## How The Retriever Surfaces Fit

| Surface | Owns | Start here when... |
| --- | --- | --- |
| Core Retriever | Flow, Pipeline, clocks, sync policies, IR, execution, replay, graph rendering, and Hub loading mechanics. | You need to understand or debug the runtime model. |
| Golden Retriever | Applied robot examples, reusable payload packs, simulator lanes, visualization demos, and pack candidates. | You want runnable robot-facing examples after the core quickstart. |
| Retriever Hub | The packaging boundary for stable Flows, type packs, and conversion helpers. | You want reuse without depending on source-tree layout. |

## Common Patterns

| Need | Start with | Avoid first |
| --- | --- | --- |
| Safe Golden smoke | `pixi run demo-golden-hub-pack` | Camera, simulator, model, or network setup. |
| Example behavior | `pixi run -e golden-local demo-perception-detection-flow` | Optional model-backed lanes. |
| Simulator integration | `pixi run demo-robosuite-mock` | Real robosuite before the mock trace works. |
| Graph visualization | `pixi run demo-pipeline-html-viz` | Screenshots or stale generated HTML. |
| Type-pack reuse | `pixi run demo-robotics-typing-catalog` | Ad hoc dict payloads or source-only imports. |

## For AI Agents And Fast Audits

Start from [`/llms.txt`](/llms.txt), then run the safe smoke sequence before editing examples:

```bash
pixi run demo-golden-hub-pack
pixi run -e golden-local demo-perception-detection-flow
pixi run demo-pipeline-html-viz
pixi run public-surface-check
```

If one fails, fix the example, task, docs, or public-surface check together. Do not add another undocumented command as a workaround.

## What Belongs Here

| Surface | Lives in Golden? | Why |
| --- | --- | --- |
| Flow, Pipeline, clocks, sync, IR, replay, execution | No | These are core runtime semantics and stay in the core Retriever docs. |
| Robot-facing payload packs | Yes | Golden defines applied `WorldState`, `BeliefGraph`, `Plan`, `Trajectory`, command/status, and conversion examples. |
| Perception, memory, language, composition examples | Yes | These are the maintained ladder after the core quickstart. |
| Camera, simulator, visualization, notebook lanes | Yes, with dependency labels | Optional lanes should not block the first run. |
| Hub-pack candidates | Yes | Golden is the proving ground before examples become reusable Hub packs. |
